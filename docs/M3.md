# M3 — Build, execução e testes (iniciado)

Status: **compilação com `javac`, diagnósticos e execução de `main` entregues como fallback**. Build lifecycles completos de Maven/Gradle, testes JUnit e debugger ainda estão pendentes.

## Entregue

### Compilação com javac
- `reclipse-ui::build` compila todos os `java_files` do projeto com o `javac` do JDK resolvido (`jdk_home`) ou do `PATH`.
- Usa `--release <target>` quando o target do projeto é conhecido.
- Usa o classpath resolvido (JARs locais) e `-proc:none`, `-encoding UTF-8`.
- Argumentos são gravados em argfile com caminhos normalizados (evita limite de linha de comando e escapes do Windows).
- Diretório de saída temporário (`reclipse-build-*`), mantido durante a execução.
- Comando: toolbar **Compilar**, menu **Projeto → Compilar com javac** ou palette.
- Diagnósticos (`arquivo:linha: error/warning: mensagem`) são exibidos no painel **Problemas** e logados no console.
- `javac: 0 erro(s)` aparece na telemetria do right dock e na status bar.

### Execução de main
- Descoberta de classes com `public static void main` no índice sintático.
- Comando **Executar** na toolbar, menu **Projeto → Executar** ou `Ctrl+F11`.
- Compila e roda `java -cp <classes>;<jars> <main>`; stdout/stderr vão para o console.
- Quando há mais de uma `main`, a primeira é executada e um aviso lista a escolha.
- O botão **Debug** permanece desabilitado: o debugger JDWP/JDI é M4.

### Split editor
- Botão **Split** na barra de abas, **Exibir → Editor dividido** e palette.
- Dois painéis lado a lado; cada aba pode ser arrastada entre os painéis via drag-and-drop (`egui::dnd_drag_source`/`dnd_drop_zone`).
- Fechar uma aba ajusta o painel secundário; abrir/ativar abas no painel esquerdo não fecha o direito.
- O editor dividido não é persistido na sessão nesta versão.

### Semântica complementar
- Overloads de método agora são escolhidos por **contagem de argumentos** (projeto e classpath), incluindo chamadas encadeadas (`service.find().`), com fallback para o primeiro overload quando não há correspondência.
- O parser registra a contagem de argumentos das chamadas e o total é usado em referências/rename/hover.
- Tipos locais são detectados; classes anônimas isolam referências não qualificadas em um container `<anonymous>`.
- Rename de pacote (com subpacotes) atualiza declarações `package`, imports, referências qualificadas e move arquivos entre source roots.
- Static imports ambíguos são ignorados em vez de escolher um dono.

## Limitações

- `javac`/`java` são fallback: não executam plugins/resources/tests, não respeitam ciclos de vida Maven/Gradle e exigem um JDK com binários.
- Não há argumentos de execução/configurações de launch, console com cancelamento, JUnit ou mapeamento de classes geradas.
- Debugger JDWP/JDI ainda não existe.
- Overloads usam apenas aridade (sem tipos de argumento, varargs ou generics completos).
- Generics completos (type arguments, type variables, wildcards, return types genéricos de bibliotecas) ainda não são resolvidos.
- Tipos locais/anônimos têm modelagem conservadora: membros de classes anônimas e tipos locais não são indexados como tipos de projeto.
- Rename de pacote não atualiza Javadoc, strings, `module-info` ou recursos; move apenas arquivos Java.
- Split editor não persiste na sessão e não tem divisão vertical/resize independente.
