# M1 — Editor de produção

Status: **concluído**, com limitações residuais listadas no fim.

O M1 transformou o editor do MVP em um editor próprio, com buffer rope, virtualização, folding, multi-cursor, busca/replace, watcher, sessão, recuperação de buffers e atalhos no padrão Eclipse.

## Editor

- Buffer `ropey::Rope`, posições por índice de caractere.
- Renderização apenas do viewport.
- Highlight incremental por linha (`Normal`, `BlockComment`, `TextBlock`).
- Inserção/remoção de linhas usa estado anterior e mapeamento de deslocamento para reaproveitar o sufixo; se o estado não convergir, recalcula o restante.
- **Folding**: marcadores na gutter; clique alterna; atalhos de teclado para dobrar/desdobrar e recolher/expandir tudo; ranges não se sobrepõem; folds são revalidados quando o número de linhas muda e **persistidos na sessão**.
- **Multi-cursor**: cursores adicionais com seleção, edição, backspace/delete, undo/redo e pintura próprios; a digitação de uma rajada vira um único passo de undo.
- **Seleção por coluna**: Alt+arrastar gera uma seleção por linha; digitar substitui todas.
- Undo/redo transacional baseado em deltas; agrupamento de digitação/backspace no cursor único e de digitação em multi-cursor.
- Enter com autoindent, Tab/Shift+Tab, copiar/cortar/colar em todos os cursores.
- Cópia múltipla junta as seleções com quebra de linha.

## Busca e substituição

- Busca literal com case-sensitive.
- Busca por **palavra inteira**.
- Busca por **regex** (`regex` crate), com erro de sintaxe exibido na UI.
- Navegação anterior/próximo e destaque de todas as ocorrências.
- Substituir atual e substituir tudo no arquivo.
- Em modo regex, a substituição expande grupos (`$1`, `${nome}`), além de `$0` para o match inteiro.
- Busca no projeto em thread separada.
- **Substituir no projeto** com confirmação:
  - aplica em arquivos fechados e em abas limpas;
  - salva abas alteradas e atualiza o índice;
  - ignora abas com mudanças não salvas;
  - expansão de grupos regex também no replace do projeto.

## Watcher e conflitos

- `notify` recursivo na raiz do projeto.
- Arquivo limpo alterado no disco: recarga automática e atualização do índice.
- Buffer sujo alterado no disco: banner com “Recarregar” ou “Manter minha versão”.
- Arquivo removido: banner e remoção do índice.
- Eventos do próprio save são ignorados por 2 s e comparados por conteúdo.
- Diretórios gerados (`target`, `build`, `out`, etc.) são filtrados.

## Sessão e keybindings

Arquivo: `%APPDATA%\Reclipse\session.json` (Windows) ou `~/.config/reclipse/session.json`.

Inclui raiz do projeto, até 100 abas com cursor/âncora e folds, aba ativa, painéis, fonte e keybindings.

## Recuperação de buffers

- Buffers sujos geram backups em `%APPDATA%\Reclipse\backups` a cada ~700 ms de alteração.
- O backup guarda conteúdo, caminho, cursor e âncora.
- Ao abrir a IDE, um diálogo lista os buffers recuperáveis com “Recuperar/Descartar” e ações em massa.
- Recuperar recria o arquivo se ele não existir; se existir, substitui o conteúdo em memória e marca como sujo.
- Save, fechar aba, reload do disco e recuperação removem o backup correspondente.
- Buffers sujos permanecem recuperáveis após fechar a IDE ou um crash.

## Benchmarks

Medição local (Windows 10, i5-4590, 4 núcleos, release, máquina ociosa):

| Cenário | Resultado |
|---|---:|
| Abrir documento de 100k linhas | 12 ms |
| Lexer completo das 100k linhas | 152 ms |
| 1.000 edições no documento de 100k linhas | 1 ms |
| Abrir 100 abas (1k linhas cada, 3,58 MB) | 18 ms |
| Índice de 2.000 arquivos Java / 26.000 símbolos | 212 ms |
| Frame CPU p95 com 100k linhas e digitação | 6,04 ms |
| Frame wall p95 com 100k linhas (vsync) | 20,92 ms |

Comandos:

```powershell
cargo run --release -p reclipse-editor --example bench_editor
```

O frame benchmark é uma feature oculta (`frame-bench`) que digita continuamente em um arquivo grande e mede o `update` completo do egui:

```powershell
cargo build --release -p reclipse-ui --features frame-bench
$env:RECLIPSE_FRAME_BENCH_FRAMES = "300"
.\target\release\reclipse.exe caminho\Bench.java
```

A janela precisa permanecer focada. Ele reporta CPU p50/p95/p99 (trabalho da UI) e wall p50/p95/p99 (inclui vsync); os valores acima usam 100k linhas.

A sessão real com 100 abas foi aberta e validada por screenshot (`docs/screenshot-100tabs.png`).

## Limitações residuais

- Backspace/delete em multi-cursor ainda são agrupados por tecla; apenas a digitação agrupa por rajada.
- “Select next occurrence” e column mode por teclado não existem; a seleção por coluna usa Alt+arrastar.
- Arquivos abertos com mudanças não salvas são ignorados no replace do projeto.
- Inserir/remover muitas linhas pode forçar recálculo do sufixo lexical; o prefixo é preservado.
- Folds dependem de heurística por chaves (`{`/`}`), não de parsing completo.
- IME/composição não foi testado a fundo.
